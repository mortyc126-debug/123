1. МАСКИРОВКА И СКРЫТНОСТЬ
================================================================================

1.1 СКРЫТИЕ ИКОНКИ ИЗ ЛАУНЧЕРА
    Файл: UtilityHelper.java → hideme()
    Метод: PackageManager.setComponentEnabledSetting() отключает ActivityAlias
    Слабость Android: приложение может отключить свои компоненты без разрешений
    Результат: иконка исчезает, приложение остаётся установленным

1.2 СКРЫТИЕ ИЗ СПИСКА НЕДАВНИХ ПРИЛОЖЕНИЙ
    Файл: UtilityHelper.java → excludeFromTaskList()
    Метод: ActivityManager.AppTask.setExcludeFromRecents(true)
    Слабость Android: API доступен без специальных разрешений
    Результат: пользователь не видит приложение в переключателе задач

1.3 МАСКИРОВКА ПОД СИСТЕМНЫЕ НАСТРОЙКИ
    Файл: AndroidManifest.xml → activity-alias "Vauplisa"
    Метод: intent-filter com.android.settings.action.IA_SETTINGS
           meta-data: com.android.settings.category.ia.development
    Слабость Android: любое приложение может заявить обработку Settings-интентов
    Результат: малварь отображается как подраздел в Настройках

1.4 ПОДМЕНА ЭКРАНА УПРАВЛЕНИЯ ХРАНИЛИЩЕМ
    Файл: AndroidManifest.xml → android:manageSpaceActivity=".Vsbjtwxrb"
    Метод: при нажатии "Хранилище" в настройках приложения открывается
           фейковый экран вместо стандартного системного
    Слабость Android: ОС безоговорочно запускает указанную Activity
    Результат: пользователь не может очистить данные через настройки

1.5 ФЕЙКОВОЕ "УДАЛЕНИЕ"
    Файл: IncompatibilityNotificationActivity.java
    Метод: показывает "Версия несовместима с устройством" на 10 языках
           кнопка "Удалить" на самом деле скрывает иконку и запускает сервисы
    Слабость: социальная инженерия
    Результат: жертва думает что удалила приложение

2. ОБХОД СИСТЕМЫ РАЗРЕШЕНИЙ
================================================================================

2.1 ПРИНУДИТЕЛЬНОЕ ПРЕДОСТАВЛЕНИЕ РАЗРЕШЕНИЙ
    Файл: PermissionsRequestActivity.java
    Метод: при отказе в разрешении выполняет:
           - Runtime.exec("pm clear " + packageName) — очистка данных
           - Удаление cache, files, databases
           - System.exit(1) — крах приложения
           Повторяет запрос при следующем запуске
    Слабость Android: приложение может удалять свои данные как "наказание"
    Результат: пользователь вынужден дать разрешения чтобы не терять данные

2.2 АВТОМАТИЧЕСКИЙ КЛИК ПО ДИАЛОГАМ РАЗРЕШЕНИЙ
    Файл: SetupOrchestrationService.java
    Метод: устанавливает флаги:
           AccessibilityServiceController.FOR_PRIMS = true
           AccessibilityServiceController.Auto_Click = true
           AccessibilityServiceController.req_hidp = true (чёрный экран)
    Слабость Android: Accessibility Service может кликать по системным диалогам
    Результат: разрешения выдаются автоматически пока экран чёрный

2.3 ПОЛУЧЕНИЕ OVERLAY-РАЗРЕШЕНИЯ
    Файл: DrawOverlayPermissionActivity.java
    Метод: если Accessibility уже есть — напрямую открывает Settings
           иначе — фейковый диалог с иконкой Google Play
    Слабость Android: MANAGE_OVERLAY_PERMISSION открывается как обычный Intent
    Результат: пользователь думает что это системный запрос

2.4 ЗАМЕНА SMS/ЗВОНКОВ ПО УМОЛЧАНИЮ
    Файл: DefaultDialerSmsActivity.java
    Метод: RoleManager API (Android 10+) для запроса роли default SMS/Dialer
           Legacy: android.telecom.action.CHANGE_DEFAULT_DIALER
    Слабость Android: пользователь не осознаёт последствия смены приложения
    Результат: полный перехват SMS и звонков

3. ЗЛОУПОТРЕБЛЕНИЕ ACCESSIBILITY SERVICE
================================================================================

3.1 ПОЛУЧЕНИЕ ДОСТУПА
    Файл: AccessibilityPromptActivity.java
    Метод: WebView-диалог "Разрешите доступ для работы приложения"
           Кнопка "Включить" → открывает Настройки Accessibility
           Кнопка "Назад" перехвачена (onKeyDown возвращает true)
    Результат: пользователь не может закрыть диалог без включения

3.2 СИНТЕТИЧЕСКИЕ ЖЕСТЫ
    Файл: AccessibilityServiceHelper.java → clickthis(x, y)
    Метод: GestureDescription.Builder + dispatchGesture()
    Применение: автоматический клик по любой точке экрана
    Результат: имитация касаний пользователя в любом приложении

3.3 ПЕРЕХВАТ PIN/ПАРОЛЯ БЛОКИРОВКИ
    Файл: AccessibilityServiceController.java
    Метод: мониторинг TYPE_VIEW_CLICKED на экране блокировки
           describePatternCells() — захват графического ключа
           checkpass() — захват цифрового PIN
    Слабость Android: Accessibility видит все UI-события включая ввод пароля
    Результат: PIN/пароль устройства отправляется на C2

3.4 ЧЁРНЫЙ ЭКРАН + БЛОКИРОВКА КАСАНИЙ
    Файл: AccessibilityServiceHelper.java
    Метод: BlackScreen_ON — чёрный оверлей поверх всего
           TouchBlockOverlay — перехват всех касаний
    Применение: пока пользователь видит чёрный экран,
                малварь кликает по диалогам разрешений
    Результат: полностью невидимые действия

3.5 СКРИНШОТЫ БЕЗ УВЕДОМЛЕНИЯ
    Файл: AccessibilityServiceController.java → takeScreenshot()
    Метод: AccessibilityService.takeScreenshot() (Android 11+)
    Слабость Android: Accessibility Service может делать скриншоты без
                      уведомления пользователя (в отличие от MediaProjection)
    Результат: скрытый захват экрана

4. ПЕРЕХВАТ КОММУНИКАЦИЙ
================================================================================

4.1 ПЕРЕХВАТ SMS (приоритет 999)
    Файл: SmsInterceptorReceiver.java (Voadet)
    Метод: BroadcastReceiver с priority="999" на SMS_DELIVER и SMS_RECEIVED
    Слабость Android: приоритетный приёмник получает SMS раньше стандартного
    Результат: все входящие SMS (включая 2FA-коды) перехватываются

4.2 ПЕРЕХВАТ ЗВОНКОВ
    Файл: MyInCallService.java
    Метод: BIND_INCALL_SERVICE + замена стандартного диалера
    Результат: контроль над входящими/исходящими вызовами

4.3 ПЕРЕАДРЕСАЦИЯ ЗВОНКОВ
    Файл: CallForwardingManager.java
    Метод: USSD-команды через TelephonyManager.sendUssdRequest()
           *#21# — проверка, **21*{номер}# — установка, #21# — отмена
    Результат: звонки жертвы перенаправляются на номер атакующего

4.4 КЕЙЛОГГЕР
    Файл: KeystrokeLogger.java
    Метод: Accessibility TYPE_VIEW_TEXT_CHANGED + TYPE_VIEW_FOCUSED
           XOR-шифрование ключом "GndZJWejB1GVLVK548VbLBWbL8w8fe"
           Хранение: /sdcard/IC/KSTR/yyyy-MM-dd.txt
    Результат: все нажатия клавиш записываются и шифруются

9. ЭКСПЛУАТИРУЕМЫЕ УЯЗВИМОСТИ ANDROID
================================================================================

#  | Уязвимость                                    | CVE/Тип
---|-----------------------------------------------|------------------
1  | Accessibility Service может кликать по         | Design flaw
   | системным диалогам разрешений                  |
2  | setComponentEnabledSetting() без разрешений    | Design flaw
3  | setExcludeFromRecents() без разрешений         | Design flaw
4  | IA_SETTINGS intent может заявить любое         | Design flaw
   | приложение                                     |
5  | manageSpaceActivity не валидируется ОС          | Design flaw
6  | BroadcastReceiver priority позволяет           | Design flaw
   | перехватить SMS раньше системного приложения    |
7  | AccessibilityService.takeScreenshot()          | Design flaw
   | без уведомления пользователя                    |
8  | WebView off-screen рендеринг с file:// доступом| Design flaw
9  | dispatchKeyEvent() может поглотить HOME/BACK   | Design flaw
10 | setShowWhenLocked() доступен для любой Activity | Design flaw
11 | DreamService запускает код на locked screen     | Design flaw

Примечание: все обходы основаны на архитектурных слабостях Android,
а не на конкретных CVE. Это делает их актуальными на большинстве
версий Android 7-14.

10. РЕКОМЕНДАЦИИ ПО ЗАКРЫТИЮ
================================================================================

10.1 Google/Android:
     - Запретить Accessibility кликать по системным диалогам разрешений
     - Требовать подтверждение пользователя для setComponentEnabledSetting()
     - Уведомлять пользователя при takeScreenshot() через Accessibility
     - Ограничить off-screen WebView с file:// доступом
     - Запретить перехват HOME/BACK в пользовательских Activity

10.2 Производители (Xiaomi, Oppo, Samsung и др.):
     - Защитить экраны автозапуска от автоматического клика
     - Добавить подтверждение биометрией для критичных настроек

10.3 Пользователи:
     - Не давать Accessibility Service непроверенным приложениям
     - Проверять список Accessibility → Настройки → Специальные возможности
     - Установить антивирус с мониторингом Accessibility
